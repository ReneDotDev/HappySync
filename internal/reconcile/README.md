# Reconciliation design

The database retains immutable operations. Each operation ID is BLAKE3 of the JSON encoding of every record field except `id`; Go's JSON encoder sorts vector keys. It binds the portable path, origin, monotonic counter, causal vector, flags, and complete manifest. Reconciliation uses causal vectors and never consults timestamps.

`Resolve` projects the maximal causal frontier at each path. Equal content projects once; `ClockFor` joins every observed operation so a subsequent local edit observes all coalesced branches. Returned records remain original immutable operations. A deletion wins over concurrent content at the original path, while the content projects to a deterministic sibling containing its operation ID. An imported candidate cannot supersede an established operation, including a tombstone. A later intentional edit that observes the tombstone can recreate the original.

Explicit operations on a generated conflict path causally supersede its generated source copy. `ClockFor` includes the source operation when asked for its conflict path. Files blocking live descendants move to a conflict sibling; live descendants of a deleted directory move to a deterministic conflict subtree. Original descendant tombstones retain their original paths. Filesystem application must delete children before cleaning up empty deleted directories.

The filesystem engine must persist its installed causal baseline, preserve raw events, and materialize installed conflict copies as deterministic ordinary records at their projected paths using the source causal stamp. Equal-content generated/materialized records coalesce, preferring the explicit materialized record. This preserves existing copies after a later main-path edit. Received metadata that was not applied cannot advance a local user edit's causal baseline. The engine must verify bytes before installation and journal filesystem changes independently of this pure projection. Case-fold or Unicode spelling collisions are visible errors that stop application rather than overwrites.

The tests check causal replacement, deletion, intentional recreation, imported candidates, content coalescing, repeated operations, 1,000 merge permutations, directory/file conflicts, derived conflict editing and deletion, and malformed records. End-to-end tests must also check persisted baseline and recovery behavior.
